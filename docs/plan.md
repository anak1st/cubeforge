# cubeforge 开发计划表

> **技术栈（已定）**：浏览器平台 · TypeScript(strict) + Vite + three.js(WebGL) + React 19 + zustand · 无 mod 系统 · 无联机 · 单机实验性游戏。
> **架构分层**：`core/`（纯逻辑，禁 three/DOM/react）→ `render/`（three）→ `game/`（循环/输入/存档）→ `ui/`（React）。依赖方向单向，ESLint 强制。
> **算法蓝本**：Luanti 与 Voxelize 引擎源码（`refs/` 只读克隆），选择性借鉴。
>
> **审核原则**：每个里程碑的验收 = 人类按"操作 → 预期"清单在浏览器里执行一遍，全程 15–30 分钟。凡是性能类指标，都写明用 DevTools 哪个面板、看哪个数字。禁止出现"代码是否优雅"这类无法人工判定的标准。

---

## 通用完成定义（每个里程碑都必须满足）

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` 全绿。
2. 人工验收清单逐条通过；失败项记录到 `docs/qa/Mxx.md`（一行一条：现象 + 复现步骤），当场修复或明确挂账到下一个里程碑。
3. `git tag Mxx` 打点（回退点），main 分支合并。
4. 每个里程碑是一次独立的 AI 协作会话可以承接的范围：会话开始时把本文件的对应章节喂给它即可。

**审核记录格式**（每个里程碑一份，5 分钟写完）：

```
## M3 验收记录 · 日期 · 验收人
| # | 操作 | 预期 | 结果 |
|---|------|------|------|
| 1 | 飞到两区块交界处 | 无破洞 | ✅ |
失败项 → 挂账：#12
```

## M0 · 工程骨架与开发回路（0.5 天）

**目标**：空壳工程，但"改代码 → 看到效果"的回路完全建立。

**任务**
- pnpm + Vite + TS(strict) + ESLint(flat) + Prettier + vitest；`@vitejs/plugin-react`。
- 建立分层目录 `src/{core,render,game,ui,workers}` 与 ESLint 分层禁令（core 不得 import three/react/DOM；render 不得 import react；ui 不得 import three）。
- React 根挂载一个占位页（标题 "cubeforge"）；挂 Tweakpane 调试面板 + FPS 计数（自写或 stats.js）。
- `package.json` 脚本：`dev / build / preview / test / lint / typecheck`；依赖锁精确版本。
- 写 `AGENTS.md`：粘贴本计划表链接 + 分层规则 + "改 core 必须带 vitest" 约定（给后续 AI 会话的常驻上下文）。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | `pnpm dev` 打开提示的地址 | 浏览器显示标题页 + FPS 显示 + 调试面板 |
| 2 | 修改 React 组件里的标题文字并保存 | 浏览器 1 秒内自动更新（HMR），无需手动刷新 |
| 3 | `pnpm test && pnpm lint && pnpm typecheck` | 全部通过，无警告刷屏 |
| 4 | 在 `src/core/` 任一文件加一行 `import * as THREE from "three"` 再跑 lint | lint **报错拦截**（证明分层规则生效） |
| 5 | `pnpm build && pnpm preview` | 产物页面正常打开 |

## M2 · 世界数据模型：方块注册表 + Chunk + World（1 天，纯逻辑）

**目标**：Luanti 式数据模型——16³ chunk、方块注册表、世界容器——在 `core/` 落地。本里程碑**不渲染任何东西**，全部成果是代码 + 测试。

**任务**
- `core/blocks.ts`：方块注册表（BlockDef：名字、贴图名、是否透明、是否实心、硬度…），注册 stone/dirt/grass/sand/leaves/water/air 占位。id ↔ 名字映射。
- `core/chunk.ts`：Chunk = 16×16×16 的 `Uint16Array`（id）+ `Uint8Array`（param1 光照预留）；坐标换算 `world↔chunk↔local`。
- `core/world.ts`：chunk 哈希表容器；`getBlock/setBlock`（跨 chunk 自动寻址）；缺失 chunk 返回约定值。
- vitest 用例（每一行都是验收项）：坐标往返、越界读写抛错或拒绝、注册表查默认值、跨 chunk set/get、16³ 全 0 初始化。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | `pnpm test` | 全绿 |
| 2 | 打开测试报告，对照下列行为逐条核对用例存在 | 坐标换算往返一致；越界有防护；chunk 外 get 返回约定值；注册表默认方块存在 |
| 3 | `grep -r "three\|document\|window" src/core/` | 零结果（core 纯度） |

> 说明：本步的"审核"就是读测试清单 + 跑命令，不需要游戏画面。这正是把纯逻辑层放最前面的原因——它是 AI 自主迭代的主战场。

## M3 · 网格化与面剔除：世界长出三角形（1.5 天）

**目标**：最小网格管线：chunk 数据 → 顶点缓冲 → 屏幕。实现"相邻同面剔除"和一张纹理图集。

**任务**
- `core/mesher.ts`：输入 chunk + 四邻查询接口，输出 `{position, uv, color|light}` 顶点数组（**纯函数**，vitest 验证：被 6 面包围的内部方块产生 0 个面，单块世界产生 6 个面）。
- 程序化高度图（simplex-noise + 种子）先出草/泥/石三层地形，让 M3 就有"真世界"可看。
- render/：运行时 canvas 合成纹理图集（先用程序生成的占位贴图：纯色+噪点即可）；BufferGeometry 装配；透明方块（树叶/水）分桶到第二个材质 pass。
- F3 调试：显示三角形总数、chunk 数；切换 chunk 边界线框。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 观察初始地形 | 起伏的山丘，草在土上、土在石上，颜色可区分 |
| 2 | 飞到两个 chunk 交界 | 无裂缝、无破洞、无重叠面闪烁 |
| 3 | 按 F3 切 chunk 边界显示 | 看到网格线；三角形总数显示为具体数字 |
| 4 | 对着平坦地面看三角形计数 → 挖掉视觉上一大片的覆盖范围（或调小临时视距） | 三角形数明显下降（证明面剔除生效） |
| 5 | `pnpm test` | mesher 纯函数用例全绿（0 面/6 面/跨界查询） |

## M4 · 无限世界与流式加载（2 天）

**目标**：Emerge 最小版：走到哪生成到哪，走远了卸载存起来。

**任务**
- game/world：按玩家位置维护加载半径（默认视距 6 chunk，设置可调 2–16）；待生成队列；卸载 = 数据保留在内存池 + 标记脏。
- workers/mesh.worker：网格生成移入 Worker（Vite module worker，手写消息协议：`{type:"meshRequest", …} / {type:"meshResult", …}`）。主线程每帧最多换入 N 个 mesh（防卡顿尖峰）。
- 生成在主线程（简化：高度图便宜）；只在 Worker 做 meshing。
- 修改方块 → 所在 chunk 及受影响的相邻 chunk 重新入 mesh 队列。
- DevTools 审核用临时开关：模拟慢生成（每 chunk 延迟 50ms），验证"进度式加载"不冻结画面。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 朝一个方向连续飞 2 分钟 | 永远有新地形出现，看不到"世界尽头" |
| 2 | 原路飞回起点 | 地形与出发时一致（同种子确定性） |
| 3 | 打开 DevTools → Performance，录制"持续前飞 20 秒" | 主线程无超过 200ms 的长任务条 |
| 4 | 观察远处地平线 | 新 chunk 以可见但温和的速度浮现，无整片闪现 |
| 5 | 快速飞行穿过约 100 个 chunk 后回望 | 画面不卡死；FPS 计数回到 ≈60（内存未失控的粗检） |
| 6 | 改变视距设置（若 M7 未到，用 Tweakpane） | 视野内 chunk 数随设置变化 |

## M5 · 第一人称：移动、碰撞、挖与放（2 天）

**目标**：游戏手感闭环：物理、AABB 碰撞、DDA 拾取、挖/放。

**任务**
- game/input：Pointer Lock（点击画面进入；ESC 由浏览器退出并触发暂停流程占位）；WASD/空格/Shift 潜行。
- game/physics：玩家 AABB（0.6×1.8）、重力跳跃、分轴碰撞 + 0.5 格自动上台阶；掉出世界底部回到出生点。
- game/interact：DDA 射线（触及距离 4 格）→ 线框选中框；左键按住挖（进度按方块硬度，裂纹贴图换 UV）；右键放置（含"不能放进自己身体"检测）。
- core 层的碰撞/射线为纯函数 + vitest（贴墙滑行、1 格台阶、命中面法向）。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 点击画面 | 鼠标锁定，出现十字准星 |
| 2 | WASD 走、空格跳 | 手感成立：能跳上 1 格，**跳不上 2 格**；按住 Shift 移动明显变慢 |
| 3 | 向墙壁走/跳 | 被墙挡住，贴墙滑行不卡顿不穿墙 |
| 4 | 从 10 格高跳下 | 平滑落地，无穿地、无弹跳异常 |
| 5 | 准星移向不同方块 | 被指方块出现黑色线框；**4 格外的方块不会被指中**（拿远处方块验证距离） |
| 6 | 按住左键对着石头 | 出现裂纹进度，约 1.5 秒后方块消失；对树叶/泥土明显更快 |
| 7 | 右键点击方块面 | 新方块出现在该面上，贴图朝向正确 |
| 8 | 准星对自己脚下的格子右键 | 放置被拒绝（不把玩家卡进方块） |
| 9 | 走到世界边缘外掉落 | 回到出生点而非无限坠落 |
| 10 | `pnpm test` | 碰撞/射线纯函数用例全绿 |

## M6 · 光照与昼夜（3 天，风险最高的里程碑）

**目标**：光照与昼夜：阳光柱 + BFS 方块光、跨 chunk 补算、平滑光照/AO、10 分钟昼夜循环。

**任务**
- core/light（纯逻辑 + 全量测试）：单通道先行？**不**——直接双通道（白天光/夜间光各 4 位存 param1），但实现顺序：阳光柱 → BFS 扩散 → 移除光源的"收光" BFS → 跨 chunk 边界欠账补算。每一步都有测试（典型场景：隧道变暗、火把半径、贴边界传播）。
- 渲染侧：光值 → 顶点色；平滑光照 + AO（邻域 4 块平均）；昼夜系数查表调色。
- 昼夜循环 10 分钟：天空颜色渐变、雾色联动、太阳/月亮 billboard（装饰即可）。
- 方块光注册：火把（光 14）；树叶遮挡阳光、水衰减（简化常数即可）。
- F3 加调试：指向方块显示其光值（0–15 数字）。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 正午站在平原 | 全亮；午夜（用 Tweakpane 拨时间）无光源时全黑 |
| 2 | 挖一条深入地下 20 格的水平隧道 | 越往里越暗，梯度平滑无跳变、无黑块噪点 |
| 3 | 隧道里放火把 | 周围出现半径约 7–8 格的渐变光圈；打掉火把光圈消失 |
| 4 | 在 chunk 边界一侧放火把 | 光跨过边界照到隔壁 chunk（重点验收项） |
| 5 | 看一次完整日出→日落（Tweakpane 加速时间） | 天空/雾色连续渐变；世界亮度随之变化；**切换瞬间帧率不掉到 30 以下**（看 FPS 计数） |
| 6 | F3 指向火把旁/隧道深处 | 显示的光值数字与亮度观感一致 |
| 7 | `pnpm test` | 光照用例全绿（收光正确性、边界欠账、阳光柱被树叶截断） |

**降级预案**：若"收光 BFS"复杂度失控，先交付"放置光照 + 重算受影响区域"，把"精确收光"降级为"局部重铺"，挂账到打磨期——验收项 3 的"打掉火把光圈消失"仍须成立，允许实现内部走重铺。

## M7 · React UI 与存档（2 天，可与 M6 并行）

**目标**：主菜单/设置/暂停/世界存取的单机版。React 层全面落地。

**任务**
- ui/store（zustand）：`phase: menu | playing | paused | settings`；设置项（视距/FOV/灵敏度/音量占位）；当前世界元信息。
- ui/screens：主菜单（世界列表 + 新建/删除 + 进入）、设置页、暂停页（ESC）。像素风 CSS Modules 基础版。
- Pointer Lock 生命周期 hook：进 UI 释放鼠标，回游戏请求锁定（用户手势内）。
- game/save：IndexedDB（idb）——世界库表（元信息 + chunk blob，id 数组 + `CompressionStream('deflate')` 压缩）、玩家位置、脏块定期回写（10s 或失焦时）；设置存 localStorage。
- 世界种子在新建时生成并持久化。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开页面 | 进主菜单（不是直接进游戏）；列表为空时显示引导文案 |
| 2 | 新建世界（输入名字）→ 进入 | 加载后可玩；再次 ESC → 暂停菜单出现，鼠标解锁 |
| 3 | 挖几个方块、走远一点 → 暂停 → 退出到主菜单 | 世界列表出现该世界 |
| 4 | 重新进入该世界 | 挖/放过的方块保持原样；玩家在退出时的位置；时间为退出时的时刻 |
| 5 | 挖方块后**立刻关浏览器标签页**再进 | 改动最多回退 10 秒内的部分（可接受），世界本体不损坏 |
| 6 | 设置页拖 FOV/视距/灵敏度 | 游戏内立即生效；**刷新页面后设置保留** |
| 7 | 删除世界 | 列表移除；再次进入确认已不存在 |
| 8 | 游戏中 ESC → 点"继续" | 鼠标重新锁定（可能需要点击一次画面，属浏览器安全限制，可接受） |

## M8 · 物品、背包与合成（3 天）

**目标**：ItemStack、掉落物实体、背包/快捷栏 UI、最小合成链。游戏性从这里开始。

**任务**
- core/items：ItemStack（id×数量×元数据预留）；物品注册表（含工具：硬度倍率）；掉落表（stone→cobble 占位规则）。
- game/entities：掉落物实体（小方块视觉、落地物理、1.5 格内吸附、进包音效占位、5 分钟消失）。
- ui/inventory：E 开关；9×4 背包 + 快捷栏；dnd-kit 拖拽换位/堆叠合并；右键拆半堆；数字键 1–9 与滚轮切换，选中槽高亮；物品图标（用图集切片成 DOM 背景或离屏 canvas）。
- 合成：2×2 随身格起步，配方：原木→4 木板、木板→工作台（放置后 3×3，先不做工作台方块则给 3×3 直接可用，二选一，实现时定）、木板+木棍→木镐/木剑；`core/crafting.ts` 纯逻辑 + 测试（shaped 匹配含平移、无序配方）。
- 挖掘联动：工具倍率（手挖石 ≈1.5s，木镐 ≈0.75s）。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 挖掉原木 | 掉出旋转漂浮的小方块；走近被吸向玩家并消失，快捷栏出现"原木×1" |
| 2 | 连续挖 4 个原木 → 按 E | 背包可见 4 组原木；拖动其中一组到另一格成功；拖到同类物品上合并数量 |
| 3 | 右键一组 10 个物品再点击空格 | 拆成 5+5 |
| 4 | 在合成格里摆 1 原木 | 输出 4 木板；摆错配方无输出；取出输入格返还物品 |

## M9 · 表现层打磨：音效、粒子、手持、水与树叶（2 天）

**目标**："从能玩到像游戏"。全部是观感项，审核以耳听眼见为准。

**任务**
- game/audio（WebAudio 原生）：挖/放/拾取/脚步音效（开源素材包占位），主音量设置接通 M7 的设置页。
- 粒子：破坏方块时迸出对应颜色的碎片（重力+落地消失）。
- 手持物品：右下角渲染当前方块/工具，走路摆动 + 点击挥动动画。
- 水：半透明蓝、水面低于方块顶、入水减速+视野蓝化（无游泳机制，浮在水面即可，挂账真游泳）。
- 树叶：alpha 镂空贴图，能透过看到后面。
- 树：生成器加树（原木+树叶簇），草地不再空旷。

**人工审核清单**
| # | 操作 | 预期 |
|---|---|---|
| 1 | 挖/放不同方块 | 有对应音效，石头"硬"、泥土"闷"；音量设置滑条生效、静音为 0 |
| 2 | 走路/跳跃 | 脚步声随步频 |
| 3 | 挖掉方块 | 迸出同色碎片，受重力落 地后消失，数量适中不刷屏 |
| 4 | 观察右下角 | 手持物存在；走路时摆动；点击时挥动 |
| 5 | 走进水里 | 移动变慢、画面色调偏蓝、水面明显高于方块中线的观感成立 |
| 6 | 穿过树叶看背后 | 透空可见，无大片黑块 |
| 7 | 新建世界环顾 | 有树；树影（光照）自然 |
